## Принятые решения

- Порты: 8311 шлюз nginx (кабинет /, API /api, OpenAPI /docs/api), 8312 Postgres, 8313 Mailpit UI. SMTP Mailpit только внутри сети compose. Все на 127.0.0.1. Перед стартом `ss -ltn` показал, что 8311-8319 свободны.
- Контейнеры: podryad-db, podryad-redis, podryad-mailpit, podryad-app (php-fpm), podryad-worker (очередь), podryad-scheduler (schedule:work), podryad-gateway (nginx + собранный кабинет + swagger-ui).

- Laravel 12 на php:8.3-fpm-alpine, свой образ podryad-php:dev (gd с freetype и шрифты DejaVu для сканов-заглушек и аватаров). Redis через predis. Авторизация: Sanctum, Bearer-токены; для <img> и скачиваний токен можно передать ?token= (middleware token.query).
- Часовой пояс приложения Asia/Almaty: «сегодня» и сроки считаются по Павлодару.
- Роли: head (руководитель: всё + настройки и пользователи), safety (специалист по ОТ: данные, подпись, подача), foreman (мастер: просмотр, черновики заявок, без подписи и правки работников), customer (представитель заказчика, отдельный раздел /api/customer).
- Заказчики и объекты общие для всех подрядчиков (чтобы заказчик видел заявки от разных подрядчиков). Справочник типов документов и профили требований принадлежат подрядчику: он настраивает их под требования конкретного заказчика.
- Светофор (App\Services\Readiness): для каждого требования берётся лучший документ этого типа (самый поздний срок, бессрочный лучше всех, группа ЭБ не ниже требуемой). Нет документа, просрочен, мала группа = «не готов». Остаток <= 30/14/7 дней = «истекает» с уровнем 30/14/7 (пороги настраиваются в организации). Для заявки дата проверки = max(сегодня, дата начала), и если документ кончается до окончания работ, это «истекает» (жёлтый) с пояснением.
- Общий статус работника = проверка по «базовым» документам (флаг is_basic: медосмотр, вводный инструктаж, ОТ, СИЗ). Дашборд считает на завтра, можно выбрать профиль требований.
- Документ без срока при наличии даты выдачи получает срок по справочнику (validity_months). ЭБ требует группу I-V.
- Заявка: номер ДП-ГГГГ-NNN, статусы draft -> submitted -> approved | remarks (после замечаний снова редактируется, подписывается и подаётся). Подписать можно только если все работники не «не готов». Подача требует подписи, хеш которой совпадает с текущими данными (sha256 канонического JSON списка). Любое изменение списка или документов делает подпись недействительной.
- Эмуляция подписи (SIGN_MODE=emulate): CMS-заглушка base64 от строк `PDEMU-CMS-v1`, base64 данных, `BIN:`, `SUBJECT:`, `SIG:` HMAC-SHA256 на APP_KEY. Сервер проверяет, что подписаны ровно текущие данные и БИН свой. Режим ncalayer: принимается DER CMS (0x30), подписант достаётся openssl_pkcs7_read, если получится; криптопроверки ГОСТ нет (следующий шаг: NCANode).
- Уведомления: команда permits:notify (планировщик ежедневно в NOTIFY_TIME по Алматы, по умолчанию 09:00). Для документа берётся порог (30/14/7, 0 = просрочен); уведомляем, если порог ниже уже отправленного (worker_documents.notified_threshold), при смене срока отметка сбрасывается. Учитывается только самый свежий документ типа у работника. Одна сводка на организацию: письмо на notify_email и всем руководителям/специалистам ОТ (через очередь, Mailpit), Telegram при наличии TELEGRAM_BOT_TOKEN и chat_id, иначе запись в журнал со статусом «logged» и в лог Laravel.
- Выгрузки: TCPDF 6 (DejaVu Sans) для PDF-списка, openspout 4 для xlsx (список на пропуск, реестр сроков, шаблон импорта, чтение импорта). ZIP: 00_Список_на_допуск_*.pdf, 00_Список_на_пропуск_*.xlsx, 00_Подпись/*.cms + подписанные_данные.json, 00_Состав_пакета.txt (что не приложено), папки NN_Фамилия_Имя_ИИН со сканами документов из профиля.
- Импорт: xlsx с листами «Работники» и «Документы» (шаблон скачивается), сначала проверка (dry run) с ошибками по строкам, потом загрузка; повторная загрузка не дублирует документы.
- Начальные данные: ТОО «Ертіс Монтаж Сервис», БИН 150340012340 (выдуманный, контрольная сумма верна), 28 работников, ИИН сгенерированы Iin::make из даты рождения с верной контрольной суммой. Сроки документов считаются от дня сидирования, поэтому картина «истекает/просрочено» всегда живая. Сканы-заглушки JPEG с надписью «ОБРАЗЕЦ УДОСТОВЕРЕНИЯ» генерируются GD, примерно у каждого девятого документа скана нет (видно в пакете). 3 объекта (ПНХЗ, ГРЭС-1, КЭЗ), 5 профилей, 3 заявки: approved (ГРЭС-1), submitted (ПНХЗ), draft с неготовыми (КЭЗ/ERG).
- Входы (пароль portal2026): head@ertis.test, ot@ertis.test, master@ertis.test; заказчики ot.pnhz@zakazchik.test, ot.gres1@zakazchik.test, ot.kez@zakazchik.test.
- Тестовые файлы пишутся в /tmp/podryad-test-files (FILES_ROOT), чтобы тесты не засоряли storage кабинета.
